# Markdown 协同编辑平台 V1 项目方案

## 1. 项目定位

V1 是一个轻量 Markdown 协同编辑平台，目标是让团队成员可以登录系统，在工作区内创建、编辑和共同维护 Markdown 文档。

V1 不做完整研发文档平台，也不引入 AI Agent 辅助编辑。第一版只聚焦一条主线：多人同时编辑一篇 Markdown 文档，并可靠保存为服务端真实 `.md` 文件。

## 2. 核心目标

- 支持用户注册、登录和基础鉴权。
- 支持工作区、成员和文档管理。
- 支持 Markdown 所见即所得编辑。
- 支持多人实时协同编辑和在线状态展示。
- 支持自动保存到服务端真实 `.md` 文件。
- 支持服务重启后从 `.md` 文件恢复文档内容。
- 支持 Docker Compose 本地部署。

## 3. V1 范围

### 3.1 V1 要做

- 邮箱密码注册、登录、退出。
- 登录态路由保护。
- 工作区创建和工作区列表。
- 工作区成员关系和基础角色权限。
- Markdown 文档创建、打开、重命名、删除。
- 所见即所得 Markdown 编辑。
- 多人实时协同编辑。
- 在线成员和连接状态展示。
- 自动保存文档内容到服务端 `.md` 文件。

### 3.2 V1 不做

- AI Agent 辅助编辑。
- 完整研发文档平台能力。
- Git 仓库同步。
- 附件和图片对象存储。
- SSO / LDAP 企业登录。
- Mermaid、数学公式、复杂目录生成等高级 Markdown 能力。

## 4. 用户角色

- `owner`：工作区拥有者，可以管理工作区、成员和所有文档。
- `editor`：可以创建、编辑、重命名和删除自己有权限的文档。
- `viewer`：只能查看文档，不能修改正文或文档元信息。

## 5. 核心用户流程

1. 用户注册或登录。
2. 用户进入工作区列表。
3. 用户创建或进入一个工作区。
4. 用户在工作区内创建 Markdown 文档。
5. 用户打开文档编辑页。
6. 多个用户同时进入同一文档并协同编辑。
7. 系统自动保存文档到服务端 `.md` 文件。
8. 服务重启后，用户再次打开文档，内容可以恢复。

## 6. 高层架构

V1 采用三个主要服务：

- `web-app`：前端单页应用，负责登录、工作区、文档列表和编辑器界面。
- `api-service`：后端 REST API，负责认证、权限、工作区、成员、文档元信息、文件路径生成和文档访问授权。
- `collab-service`：实时协作服务，负责 Yjs 文档同步、在线状态、正文加载、正文保存触发和协同状态持久化。

详细技术设计见 `V1 技术方案.md`。

## 7. 第一轮交付目标

第一轮先搭建可运行工程骨架，不一次性完成完整 V1。

第一轮完成后应具备：

- `pnpm` monorepo 基础结构。
- 前端 `web-app` 可以启动并访问基础路由页面。
- 后端 `api-service` 可以启动并提供健康检查接口。
- 协同服务 `collab-service` 可以启动 WebSocket 服务。
- PostgreSQL 可以通过 Docker Compose 启动。
- Prisma schema 建立 V1 核心数据模型。
- Docker Compose 能描述本地开发所需服务。

第一轮施工细节见 `第一轮施工计划/README.md`。
