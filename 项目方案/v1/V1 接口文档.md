# Markdown 协同编辑平台 V1 接口文档

## 1. 文档定位

本文档记录 V1 对外 REST API 和服务内部接口。项目目标和范围见 `V1 项目方案.md`，服务边界和实现约定见 `V1 技术方案.md`。

## 2. REST API

REST API 由 `api-service` 提供，主要负责认证、工作区、成员和文档元信息。文档正文由 `collab-service` 通过协同协议加载和保存，V1 不提供独立的正文保存 REST API。

### 2.1 Auth

```http
POST /auth/register
POST /auth/login
GET /auth/me
POST /auth/logout
```

`POST /auth/register` 请求体：

```json
{
  "email": "user@example.com",
  "displayName": "User",
  "password": "password"
}
```

`POST /auth/login` 请求体：

```json
{
  "email": "user@example.com",
  "password": "password"
}
```

登录成功返回：

```json
{
  "accessToken": "jwt-token",
  "user": {
    "id": "user_id",
    "email": "user@example.com",
    "displayName": "User"
  }
}
```

### 2.2 Workspace

```http
GET /workspaces
POST /workspaces
GET /workspaces/:workspaceId
GET /workspaces/:workspaceId/members
POST /workspaces/:workspaceId/members
DELETE /workspaces/:workspaceId/members/:memberId
```

V1 可以先只做最小成员管理：

- 创建工作区时，当前用户自动成为 `owner`。
- `owner` 可以添加已注册用户为 `editor` 或 `viewer`。
- 暂不做邮件邀请链接。

### 2.3 Document

```http
GET /workspaces/:workspaceId/documents
POST /workspaces/:workspaceId/documents
GET /documents/:documentId
PATCH /documents/:documentId
DELETE /documents/:documentId
```

`POST /workspaces/:workspaceId/documents` 请求体：

```json
{
  "title": "新文档"
}
```

`PATCH /documents/:documentId` 请求体：

```json
{
  "title": "更新后的标题"
}
```

说明：

- REST API 管文档元信息。
- 文档正文由协同服务加载和保存。
- V1 不提供独立的正文保存 API，避免和协同保存路径冲突。

## 3. 内部接口

内部接口只用于服务之间调用，不提供给 `web-app` 直接调用。

### 3.1 INT-001 文档访问校验接口

用途：

- `collab-service` 在建立协同连接前，向 `api-service` 校验当前用户是否可以进入指定文档房间。
- `api-service` 返回该用户对文档的访问结果、只读状态、角色和授权后的 Markdown 文件相对路径。

调用方：

- `collab-service`

提供方：

- `api-service`

接口：

```http
POST /internal/documents/:documentId/access
Authorization: Bearer <accessToken>
```

路径参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `documentId` | `string` | 是 | 要进入协同房间的文档 id |

请求头：

| 名称 | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | 用户登录后获得的 access token，格式为 `Bearer <accessToken>` |

请求体：

V1 默认可以为空。后续如果需要审计或风控，可以追加连接来源信息。

```json
{}
```

成功返回：

```json
{
  "allowed": true,
  "readonly": false,
  "documentId": "doc_123",
  "workspaceId": "ws_001",
  "filePath": "workspaces/ws_001/documents/doc_123.md",
  "role": "editor"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `allowed` | `boolean` | 是否允许进入文档房间 |
| `readonly` | `boolean` | 是否只能只读进入 |
| `documentId` | `string` | 文档 id |
| `workspaceId` | `string` | 文档所属工作区 id |
| `filePath` | `string` | 授权后的 Markdown 文件相对路径 |
| `role` | `'owner' | 'editor' | 'viewer'` | 当前用户在工作区内的角色 |

权限语义：

- `owner`：`allowed=true`，`readonly=false`。
- `editor`：`allowed=true`，`readonly=false`。
- `viewer`：`allowed=true`，`readonly=true`。
- 非工作区成员或无权访问该文档：不允许进入。

失败返回：

| HTTP 状态码 | 场景 | 说明 |
| --- | --- | --- |
| `401` | 未登录或 token 无效 | `collab-service` 应拒绝建立协同连接 |
| `403` | 无权限访问文档 | `collab-service` 应拒绝建立协同连接 |
| `404` | 文档不存在 | `collab-service` 应拒绝建立协同连接 |
| `500` | 服务端错误 | `collab-service` 应拒绝连接或提示稍后重试 |

安全约束：

- 该接口只能由服务端内部调用，不应作为公开前端 API 使用。
- `filePath` 必须由 `api-service` 根据 `workspaceId` 和 `documentId` 生成，不能使用客户端传入路径。
- `collab-service` 只能使用该接口返回的 `filePath` 读写 Markdown 文件。
- `collab-service` 不复制 workspace membership 和角色判断逻辑。
