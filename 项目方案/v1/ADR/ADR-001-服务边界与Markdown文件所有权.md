# ADR-001: V1 服务边界与 Markdown 文件所有权

## 状态

已接受。

## 背景

V1 同时包含 REST API、实时协同服务和 Markdown 文件持久化。如果 `api-service` 和 `collab-service` 都直接实现权限规则和文件路径规则，后续会出现权限不一致、路径生成重复、保存流程冲突等问题。

## 决策

- `api-service` 是业务事实来源，拥有认证、权限、工作区、成员、文档元信息和文件路径生成规则。
- `collab-service` 是协同运行时，拥有 Yjs 房间、连接状态、协同状态同步和后续正文保存触发。
- Markdown 文件路径只能由 `api-service` 生成和授权。
- Markdown 正文运行时加载和保存由 `collab-service` 执行，但必须基于 `api-service` 的授权结果。
- 权限规则只在 `api-service` 实现，`collab-service` 通过内部接口消费授权结果。
- `packages/shared` 只承载类型和契约，不承载业务实现。

## 后果

收益：

- 权限规则有单一来源。
- 文件路径规则不会在两个服务中分叉。
- 协同服务可以专注实时协作和保存节流。
- 共享包不会变成跨端业务杂物包。

代价：

- `collab-service` 对 `api-service` 有运行时依赖。
- 需要定义内部文档访问校验接口。
- 本地开发和 Docker Compose 需要保证服务启动顺序和网络地址清晰。
